# Theoretical Context: Locator Hierarchy & Semantic Selectors

## Production Incident: Monzo Banking UI Design System Update (2021)

In 2021, UK digital bank Monzo rolled out a major design system refresh across its web and mobile onboarding platforms, updating button styles, CSS grid layouts, and class name conventions. Within an hour of merging the design token changes, Monzo's automated regression pipeline reported over 800 broken end-to-end tests across 14 engineering squads. The tests had been written using brittle CSS class locators (such as `.sc-bdVaJa.bYxKLo` generated by CSS-in-JS compilers) and structural XPath selectors (`//div[2]/form/div[3]/button`). While the application was completely functional and visually immaculate for real users, the test suite collapsed entirely due to its tight coupling to ephemeral implementation details.

## The Underlying Mechanism

Locators form the connective tissue between test automation scripts and the application DOM. Locators exist along a strict resilience hierarchy:

1. **Tier 1 (Brittle - Avoid)**: Auto-generated class names (e.g., `.css-19zjgj`), absolute XPath paths (`/html/body/div[1]/...`), and structural indexes (`div:nth-child(4)`). These change with every build, redesign, or layout refactoring.
2. **Tier 2 (Fragile - Use with Caution)**: Generic CSS selectors (`input[type="text"]`), un-scoped IDs that may collide in micro-frontends (`#save-button`), or transient HTML tag hierarchies.
3. **Tier 3 (Resilient - Recommended)**: Dedicated test IDs (`data-testid="order-submit"`).
4. **Tier 4 (User-Facing / Semantic - Gold Standard)**: Accessibility role selectors (`page.getByRole('button', { name: 'Submit Payment' })`), label locators (`page.getByLabel('Email Address')`), and text anchors. These reflect how assistive technologies and real humans interact with the interface.

```
[Locator Resilience Hierarchy]
  ┌──────────────────────────────────────────────────────────┐
  │ 🌟 Tier 4: User-Facing Roles (getByRole, getByLabel)     │ ── Resilient to CSS/DOM refactoring
  ├──────────────────────────────────────────────────────────┤
  │ 🛡️ Tier 3: Dedicated Test IDs (getByTestId)              │ ── Explicit test contract
  ├──────────────────────────────────────────────────────────┤
  │ ⚠️ Tier 2: IDs, Static Tag Selectors                     │ ── Moderate maintenance risk
  ├──────────────────────────────────────────────────────────┤
  │ ❌ Tier 1: Generated CSS Classes & Absolute XPaths       │ ── Extreme Flakiness & CI Failure
  └──────────────────────────────────────────────────────────┘
```

Adopting user-facing role locators ensures that tests only fail when user functionality actually breaks, aligning test verification with genuine accessibility standards.
